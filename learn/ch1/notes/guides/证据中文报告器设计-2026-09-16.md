# 证据中文报告器设计（render_report）

> 状态：设计已与本人讨论定稿（2026-09-16 会话）｜ 性质：learn/infra 工具设计（AI 代办区，AGENTS.md §1）
> 关联：上游 chapter1/context/vis_validation.py（布局观感复刻对象，零修改零依赖）；learn/infra/render_ablation_figure.py（SVG 速览，保留并存）
> 分层阅读：本设计 → 实施计划（writing-plans 产出）→ 代码

## 1. 背景与目标

本人实测证据（第二轨 `learn/ch1/evidence/*.json`）目前只能看 json 原文或等宽字符表格；上游可视化器
`vis_validation.py` 界面形态好（汇总表 + 每臂折叠节）但全英文、且直接喂第二轨 json 会残缺（schema 不同构）。

目标：**一个中文化 HTML 报告内核 + 每实验一个转换器文件**，实现「选哪个 evidence 文件都能渲染出完整中文分析」；
后续新实验只新增转换器文件，不改任何已有文件。

## 2. 架构（包结构）

```
learn/infra/report/
├── __init__.py              # 注册表：{"context": transforms.context.transform, ...}（显式 dict，grep 可见）
├── core.py                  # Report 通用中间模型（标准形状定义 + 构造校验）
├── render_report.py         # CLI 入口 + 中文 HTML 渲染内核（只认 Report 形状，零实验知识）
└── transforms/
    ├── __init__.py
    └── context.py           # context 转换器（后续每实验一个文件）
```

- **职责分层**：渲染内核不认识任何实验；实验知识全部在转换器；注册表是显式 dict（不做目录扫描魔法）。
- **加新实验的成本**：新增 `transforms/<exp>.py` + `__init__.py` 注册一行（+ 可选 contracts 产物声明），已有文件零改动。
- 与仓库既有组织哲学一致：probes 每探测一文件、variants 每变体一目录。

## 3. Report 通用中间模型（core.py）

```python
Report = {
  "title": str,                       # 报告标题（如 "context 消融实验报告"）
  "meta": [str],                      # 顶部 meta 行（数据源/模型/生成方式）
  "task": str | None,                 # 任务卡片（上游界面有，消融场景为案例描述）
  "summary_columns": [                # 汇总表列声明（每实验自定义 → 增强列需求天然满足）
      {"key": "arm", "title": "消融臂", "align": "left"}, ...
  ],
  "arms": [
      {
        "name": str, "code": str,                 # 显示名 / 代码名（锚点）
        "badge": {"text": "✓|✗|⚠|—", "kind": "ok|fail|warn|na"},
        "cells": {key: str},                      # 键与 summary_columns.key 对应
        "sections": [                             # 每臂折叠节，顺序即显示顺序
            {"title": str, "kind": "pre|list|table|note|kv", "content": ...},
        ],
      }, ...
  ],
  "footnotes": [str],                 # 页脚说明（数据源/降级规则/重生成方式）
}
```

section 五种 kind 覆盖全部已知需求：`pre`（全文块）/ `list`（编号列表）/ `table`（小表）/ `note`（灰字说明）/ `kv`（键值对）。
core.py 提供 `make_report()` 构造函数做形状校验（缺字段/类型错直接报错，转换器写错当场暴露）。

## 4. context 转换器（transforms/context.py）

输入：第二轨 summary json（数组形状，字段 test_name / case_name / context_mode / execution_time /
iterations / num_tool_calls / completed / success / has_final_answer / grounding_verdict /
observation_count / unsupported_quantities / error / reasoning_steps / final_answer_preview），
自动识别：记录含 `context_mode` 字段即命中 context 转换器（`--exp` 可显式覆盖）。

汇总表列（布局复刻上游 + 增强列）：

| 列 | 来源 | 说明 |
|---|---|---|
| 消融臂 | context_mode → 中文名 + 代码名 | ARM_CN 映射 |
| 书图预期 | BOOK_EXPECTATION 映射（设计意图） | 注明"书图含无工具定义臂，代码未设" |
| 跑完? | completed | ✓/✗ |
| 耗时 | execution_time | 秒 |
| 轮次 / 工具调用 | iterations / num_tool_calls | |
| grounding 判定（增强） | grounding_verdict | ungrounded 红标 |
| 编造数字数（增强） | len(unsupported_quantities) | >0 红标 |

每臂 badge 规则：`completed == False 或 has_final_answer == False → ✗ 未完成`；
`grounding_verdict == "ungrounded" → ⚠ 有答案但编数字`；否则 `✓ 正常完成`。

每臂折叠节：

1. 最终答案（pre：final_answer_preview；无答案显示 note）
2. grounding 详情（table：unsupported_quantities 逐个数，红；无编造显示"未发现编造"）
3. 工具调用记录（note 降级："该模式记录粒度为计数（N 次调用）"；若输入是单任务 json
   `task_result_*.json`（含 tool_calls 数组）→ 自动升级为逐条 list：工具名/参数/结果/时间戳）
4. 推理过程（note 降级："记录粒度为计数（N 步）"，同上：单任务 json 有全文则 list 升级）
5. 错误信息（kv，error 非空时）

页脚 footnotes：数据源文件名、路由（provider/model 见证据）、badge 规则、重生成命令、
书图臂差异说明、本报告为可视化不入 evidence/。

## 5. CLI（render_report.py）

```powershell
.venv\Scripts\python.exe learn\infra\render_report.py --input <evidence.json> [--output <path.html>] [--exp <name>] [--open] [--port 8933]
```

- `--exp` 可省略：按字段指纹自动识别（识别失败才必填）；
- 默认写单文件自包含 HTML（无外部资源）到 `--output`（缺省 `learn/ch1/notes/assets/<输入名>_report.html`）；
- `--open`：起临时本地 HTTP 服务并打印 URL（形态同上游界面），Ctrl+C 停止。

## 6. run.py 上游产物转录（纳入首期）

- `contracts.py` 每实验新增 `artifacts` 声明：上游会写出的产物文件名（相对 cwd，支持通配），如
  context：`("ablation_results.json", "task_result_*.json")`；
- `run.py --evidence`：子进程结束后，对声明清单逐个 glob，命中即**复制改名**转录进
  `EVIDENCE_DIR/{ts}_{exp}_{原名}`（纯复制零解析，仍是零实验知识；json 入库约定不变）；
- 上游照旧在 cwd 写自己的产物（上游零修改）；转录失败（无产物）静默跳过并打印提示行；
- 历史证据不受影响（纯新增行为）；HANDOFF 已有先例「产物均已移出上游 chapter1/context/」。

## 7. 后续实验扩展（可复用性承诺）

| 实验 | transforms/<exp>.py 要做的 | 上游数据源 |
|---|---|---|
| search-codegen | 解析回执 json → 列（任务/轮次/产物）+ 折叠节（逐请求回执） | 上游 receipts/run json |
| image-gen-workflow | 解析 manifest → 列（路线/尺寸/耗时）+ 节（生成图清单） | 上游 manifest |
| learning-from-experience | 解析实验结果 → 列（局数/胜率/双臂对比）+ 节 | 上游 experiment_results.json |

每个 = 一个转换函数 + 列声明；渲染内核与已有转换器零改动。若上游产物未进 evidence/，
在该实验的 contracts `artifacts` 清单里补声明即可。

## 8. 与既有产物的关系

- **SVG 对照图保留**（render_ablation_figure.py）：速览场景（笔记嵌图、GitHub 渲染）；HTML 报告是深挖
  场景（交互折叠）。速览/深挖互补，笔记两者都挂；
- **上游 vis_validation.py 不改、不 import**：布局观感复刻（同款汇总表 + 折叠节 + 色系），文案全中文；
- **run.py 元数据 json 格式不变**：转录机制是纯新增行为。

## 9. 验收标准

1. 对 `20260915T0021_context_run2_results.json` 渲染：汇总表 5 臂 × 8 列（含两个增强列），
   badge 与既有对比矩阵一致（✓✗✓⚠⚠，no_history 臂 completed=false 必为 ✗），编造数字（9/10 个）红标并列出明细；
2. 每臂折叠节可展开，降级文案正确（"记录粒度为计数"）；
3. `--open` 起服务出界面，中文无乱码（utf-8）；
4. 转录增强：构造假产物文件验证转录改名逻辑（临时目录，不污染上游 cwd）；
5. `run.py --list` 与现有证据文件零回归（转录增强不改任何既有字段）。

## 10. 不做的事（YAGNI）

- 不改上游任何文件；不 import 上游代码；不解析重组领域数据进 run.py 元数据；
- 不做插件框架（entry_points/自动扫描）——显式 dict 注册足够；
- 不做逐像素复刻上游界面（布局与信息架构对齐，视觉细节允许中文化适配）；
- 不在本期做 reasoning 全文的证据 schema 增强（上游消融模式本身不记录全文；待单任务模式
  逐臂重跑的实验需求出现再议）。
